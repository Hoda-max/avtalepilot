Project build plan

AvtalePilot MVP

A beginner-friendly web app for one organization first, built so multiple organizations can be added later without rewriting the core.

1. Simple tech stack

These tools work well together and are easy to learn with Cursor’s help.

2. Product scope for MVP

In scope (first version)

  • Sign in for staff of one organization
  • Contract library: create, edit, view, search/filter
  • Fields: title, supplier, cost, owner, department/location, status, notes
  • Key dates: renewal, expiry, notice deadline
  • Upload and view the original contract file
  • Reminders/tasks for upcoming deadlines
  • Decision record: Renew / Renegotiate / End
  • Simple overview of upcoming deadlines

Later (not in MVP)

  • AI extraction from PDFs
  • Email and calendar sync
  • Cost forecasting dashboards
  • Full multi-company signup and billing
  • Complex permission systems beyond Admin / Member

3. Ready for many organizations later

From day one, every business table includes organization_id.

  • MVP creates one organization and attaches all users to it
  • Queries always filter by the signed-in user’s organization
  • Supabase security rules (RLS) enforce that boundary
  • Later: add “create organization / invite users” without redesigning contracts

4. Data model (core tables)

Table What it stores
organizations Company id and name
profiles User, organization, name, role (admin or member)
suppliers Supplier name and contact info per organization
contracts Title, supplier, owner, location, cost, status, notes, document
contract_dates Renewal, expiry, or notice date for each contract
reminders Due date, assignee, and status (pending / done / dismissed)
decisions Renew, renegotiate, or end — who decided and when

This answers four everyday questions: Where is the contract? When must someone act? Who is responsible? What decision was made?

5. App screens

  1. Login
  2. Dashboard — upcoming deadlines and open reminders
  3. Contracts list — search and filters
  4. Contract detail — dates, file, reminders, decisions
  5. New / edit contract — including file upload
  6. Suppliers list — simple directory
  7. Settings — org name (admin); invites later

UI language: Norwegian for users; code and technical names in English.

6. Build phases

0

Project setup

  • Create Next.js + TypeScript + Tailwind in the Avtalepilot folder
  • Create a Supabase project and connect environment variables
  • Add login helpers and a protected app layout
1

Auth + single organization

  • Email/password sign-in
  • Organizations and profiles with security rules
  • Seed one organization; first user as admin
  • Send guests to the login page
2

Contract library + suppliers

  • Create, read, update, delete for suppliers and contracts
  • Store PDFs in Supabase Storage
  • List and detail pages with search and filters
3

Dates, reminders, decisions

  • Multiple date types per contract
  • Reminders ahead of notice / renewal / expiry (for example 90 / 30 / 7 days)
  • Record Renew / Renegotiate / End with history
  • Dashboard of items that need attention
4

Polish and deploy

  • Empty states, validation, clear error messages
  • A few sample contracts for demos
  • Deploy to Vercel and write a short README

7. How you will work in Cursor

  1. Approve this plan
  2. Implement one phase at a time
  3. After each phase, click through the app and give feedback
  4. Wait on AI extraction and multi-company signup until the single-org MVP feels solid

8. Success criteria

An organization user can add a contract with a file and key dates, see who owns it, get reminded before a deadline, record renew / renegotiate / end, and find that history later — all inside one organization, with the database ready for more organizations later.
